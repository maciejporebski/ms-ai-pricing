# Azure AI Foundry Model Pricing Explorer

A static React (Vite) site for looking up and comparing **Azure AI Foundry model
pricing** from the [Azure Retail Prices API](https://prices.azure.com/api/retail/prices)
(`serviceName eq 'Foundry Models'`). Built to be hosted on **GitHub Pages**.

It exists because the official pricing pages and the pricing calculator often lag
behind the Retail Prices API and omit many model SKUs. This tool reads the raw API,
normalizes the messy meter names into comparable rows, and lets you slice the data.

## Features

- **Filters** — provider, model, region, deployment type, category, free-text search,
  and a toggle to hide low-confidence (heuristically-ambiguous) rows.
- **Comparison table** — models as rows, deployment types (Global / Data Zone /
  Regional / Batch / Provisioned / Fine-tuning) as columns. Each cell shows
  Input / Output / Cached-input price **per 1M tokens**. `*` marks prices that vary
  by region (hover for the range); pick a region to pin a single price.
- **Cost calculator** — enter expected monthly input / output / cached token volumes
  (in millions) and get every matching model+deployment ranked cheapest-first, with
  per-component prices and partial-cost warnings when a meter is missing.
- **Model detail drawer** — click any model to audit the raw Azure meters behind the
  normalized numbers (meter name, SKU, unit, region, effective date) and export them.
- **CSV export** — export the filtered dataset or a single model's raw meters.
- **Shareable URLs** — filter and tab state is encoded in the query string.
- **Freshness banner** — shows the snapshot timestamp and warns if it is over 72h old.

## How the data works (and why)

The Retail Prices API does **not** send `Access-Control-Allow-Origin`, so a browser
on `github.io` cannot call it directly. Instead, a Node script fetches and normalizes
the data at build time into a static JSON snapshot that the site loads at runtime:

```
npm run fetch-data   # pages the API, normalizes, writes public/data/{pricing,meta}.json
```

`scripts/normalize.mjs` contains the heuristic parser that derives provider, deployment
type, token direction (input/output/cached), category, and a `pricePer1M` normalized
token price from the free-text `productName` / `skuName` / `meterName` fields. Raw meter
names are always retained so every number is auditable in the UI. Prices are only
normalized to "per 1M tokens" for confidently token-based units (`1M`, `1K`).

> Retail USD estimates only — they exclude discounts, reservations, EAs, taxes, and
> account-specific pricing. Verify in the Azure portal before purchase.

## Local development

```bash
npm install
npm run fetch-data     # generate the snapshot (required once; gitignored)
npm run dev            # http://localhost:5173
```

## Tests

```bash
npm run test:unit      # node --test — parser/normalizer fixtures
npm run test:e2e       # Playwright — filters, table, calculator, drawer, deep links
```

## Deploying to GitHub Pages

1. Push this repo to GitHub.
2. In **Settings → Pages**, set **Source = GitHub Actions**.
3. The workflow in `.github/workflows/deploy.yml` runs on push to `main`, on manual
   dispatch, and **daily at 06:00 UTC** to refresh the snapshot. It fetches fresh data,
   runs the unit tests, builds with the correct base path (`/<repo>/`), and deploys.

The pricing snapshot is regenerated by CI on every deploy, so it is gitignored and never
bloats the repository history.
